# ADR-001. Границы сервисов

Booking Service хранит пользователей и брони. Hotel Service хранит отели, номера и временные слоты. API Gateway только маршрутизирует и проверяет токен. Eureka даёт адреса.

Общей базы нет. Номер в брони — это идентификатор из Hotel, без внешнего ключа между базами.

# ADR-002. Двухшаговое подтверждение

Глобальной транзакции нет. Booking фиксирует `PENDING`, затем вызывает `confirm-availability`. Успех переводит бронь в `CONFIRMED`. Отказ Hotel переводит её в `CANCELLED` без `release`: слот не создавался. Таймаут или ошибка после повторов вызывает `release` и ставит `CANCELLED`.

Повтор одного `requestId` возвращает прежний результат и не создаёт вторую бронь.

# ADR-003. Рекомендация без статистики

Свободный номер — операционно доступный и без пересечения дат. Рекомендация сортирует тот же набор по `times_booked` по возрастанию, при равенстве по id. Отдельной модели прогноза нет.

# ADR-004. Интервал проживания

Интервал полуоткрытый: день выезда не занят и может быть днём заезда следующей брони. `rooms.available` означает ремонт, а не календарь.
